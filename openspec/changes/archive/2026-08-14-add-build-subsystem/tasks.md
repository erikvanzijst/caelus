## 7. Build worker

- [x] 7.1 Add `api/app/build_worker.py` as a single repeating non-blocking pass: claim, advance every running build, recover. No step may block for the duration of a build — `run_pass()` advances every running build, *then* claims, so a slot freed this pass is reused immediately rather than an interval later.
- [x] 7.2 Claim the oldest `queued` build atomically (`UPDATE ... WHERE id = (SELECT ... FOR UPDATE SKIP LOCKED LIMIT 1) RETURNING`), mirroring `JobService._claim_next_job_postgres`, and only while running builds are below the configured in-flight limit — dialect-split like `JobService.claim_next_job`: `FOR UPDATE SKIP LOCKED` on Postgres, `UPDATE ... WHERE id = (SELECT ...) RETURNING` on SQLite.
- [x] 7.3 Create the Kubernetes Job: named `build-{build_id}`, labeled `caelus.dev/build-id`, with a presigned GET for the artifact injected as an environment variable, resource limits, `emptyDir.sizeLimit`, `activeDeadlineSeconds`, and `ttlSecondsAfterFinished` — `app/services/build_jobs.py`; `backoffLimit: 0`, permissionless SA with `automountServiceAccountToken: false`, seccomp+AppArmor Unconfined, two bounded emptyDirs (work 2Gi, buildkit 6Gi) and an 8Gi ephemeral-storage limit.
- [x] 7.4 Record `job_id` only after the Job is created, so a crash in between leaves a recoverable null — and a null `job_id` also deletes any Job at the deterministic name, so a build being given up on cannot leave a runaway pod.
- [x] 7.5 On each pass, re-read every running build's Job output and store it as the build's log, truncating at the configured cap with an explicit marker, and never shortening the stored log when a read returns less than what is stored. **The log column is `bytea` (D12), so the read must stay binary end to end**: `app/proc.py`'s `CommandRunner` is typed `CompletedProcess[str]` and decodes, which would reintroduce exactly the lossy conversion the column type exists to avoid — read the Job's output without `text=True` and store the raw bytes. The truncation marker is an ASCII byte string. — binary end to end: `read_log` bypasses `app/proc.py` (which decodes) and returns raw bytes. `merge_log` discards a read shorter than what is stored.
- [x] 7.6 On each pass, derive every running build's outcome from its Job: success with a parsed termination message sets `succeeded` with the image; unsuccessful termination, a missing Job, a null `job_id`, or success reporting no usable image sets `failed`
- [x] 7.7 Apply the deadline backstop: delete the Job and fail the build when it is still active past the deadline plus grace
- [x] 7.8 Add a `build-worker` command to `api/app/cli.py` mirroring the existing `worker` command, with signal handling and graceful shutdown — no `--concurrency`, since concurrency is `--max-in-flight`, not a process count.
- [x] 7.9 Tests with a faked Kubernetes client: claim is atomic under concurrency; no claim while at the in-flight limit; a queued build is claimed once capacity frees; Job created after the status transition; log mirrored across passes and truncated at the cap; a shorter read does not shorten the stored log; success adopts the image; non-zero exit fails; success with no image fails; a finished Job is adopted after a worker restart rather than failed; a null `job_id` fails; an over-deadline Job is deleted — 43 tests against a `FakeCluster` at the `BuildJobClient` seam, with a real SQLite database (the claim is a database-level property; faking it would test nothing).
